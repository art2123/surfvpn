### Какой CPM ставить

Текущий кабинет **TLGM / getSurfVPN** — EUR (`_eur` в коде связки). Ставки TON и евро не сравнивать как одно число.

Ориентиры RU VPN (EUR-кабинет, 2026): clearing ниши часто ~€2–6 факт (у Blanc на похожих каналах). Старт у **нижней границы Recommended** больше не используем — слишком долго до объёма.

**CPM — потолок** (second-price): платим примерно цену второго места, не всегда свой бид. Высокий потолок = чаще выигрываем и *можем* платить дороже при жёсткой конкуренции. Быстрый слив daily чаще = **переплата потолка**, не обязательно кликбот.

**Страховка слива = daily €5**, не низкий старт. Низкий потолок экономит копейки и жрёт календарь до CTR/s2t/t2b.

#### Две фазы: Discovery → Settle

| Фаза | Когда | Цель | CPM |
|---|---|---|---|
| **Discovery** | первые ~24–48ч Active, пока views мало | **views или kill** | старт near clearing; грубые бампы при недоливе |
| **Settle** | показы уже идут | читать воронку; не трогать ставку | бамп только при недоливе; вниз только при переплате daily |

В Discovery **не** оптимизируем «минимальный CPM». В Settle **не** оседаем вниз «на всякий случай» в первые дни — экономия маленькая, риск снова уйти в недолив большой.

#### Settle: ↑ / ↓ / не трогать (дневной `/ad/…/stats`)

Ставка — рычаг **объёма**, не «качества». Дорого/дёшево смотрим не по потолку в поле CPM, а по **факту и темпу**. Страница `ads.telegram.org/account/ad/{id}/stats` — дневные views / spend (и CTR).

| Сигнал | Как | Смысл |
|---|---|---|
| **Views/день** | столбик показов | есть ли открут |
| **Spend/день** | столбик денег | темп vs `daily` |
| **Эфф. CPM** | `spent / views × 1000` | сколько **реально** платите (second-price) |

Потолок в кабинете ≠ цена. **Эфф. ≪ потолка** = запас; **эфф. ≈ потолка** = аукцион упирается в ваш бид.

Сначала один вопрос: **недолив или переплата?** Не оба сразу.

| Ситуация (тренд 2–3 дня, не один шумный день) | Действие |
|---|---|
| Views падают / daily не выбирается, бюджет живой | **недолив → бамп** по сетке |
| Daily сгорает рано при нормальных views (≥50% daily за &lt;6ч или ≥80% за &lt;3ч) | **переплата → −~20%** |
| Views стабильны, daily доживает, воронка читается | **не трогать** |
| Views падают, эфф. растёт к потолку | конкуренция ↑ → **мелкий бамп**, не − |
| Устойчивый открут, 2–3 дня эфф. ≤ ~60–70% потолка **и** daily доживает | **пробно снизить** потолок ≈ `эфф × 1.25…1.4` (не впритык к факту) |
| Stopped `daily < daily_spent` на Scale/Keep | **поднять daily**, не резать CPM |

Мягкое снижение — только в Settle (уже есть объём), цель **сохранить порядок views**. Сутки после − : views просели заметно → вернуть потолок. Экономия копеек не стоит потери сигнала.

Ловушки:

- Мало spend при живом daily ≠ «надо снизить» — часто **недолив** → бамп.
- Много spend при нормальном эфф. и views = открут; смотреть воронку, не ставку.
- Высокий потолок сам по себе не «дорого» — дорого, если **эфф.** высокий.
- Низкий CTR / слабый s2t → креатив/площадка, **не** направление CPM.
- Просадка одного дня (мало постов, выходные) без тренда 2–3 дней → не трогать.

Чеклист на stats: (1) эфф. vs потолок → (2) views-тренд → (3) pace vs daily → (4) CTR/воронка; ставка — последний рычаг.

### Зачем бампать CPM

Бамп нужен **только чтобы выиграть аукцион и получить показы** (недолив). Не для «улучшения качества» и не потому что прошло N часов само по себе.

- Есть показы и воронка живая → **не бампать**, смотреть покупки/триалы (фаза Settle).
- Показов почти нет при живом бюджете → бамп по сетке ниже (до потолка ~€7–9), иначе связка бесполезна.
- Уже €8–9+ и всё ещё тишина после окна Discovery → **Hold**, не дожимать.

Цель ранней фазы: **быстро набрать объём для решения**. Минимальный устойчивый CPM ищем только после живых показов (и только вниз при переплате daily).

### Перед любым повышением CPM (обязательно 3 проверки)

Смотреть **площадку** (все наши связки на этот `@login` / slug), не одну строку:

1. **История показов на других CPM.** Были ли views/spent на этом канале/боте при более низком CPM (другие `tx`, старые Deleted/Stopped)?  
   - **Да, крутилось дешевле** → не задирать сильно; недолив локальный или потолок уже высокий → Hold / мелкий шаг, не +€2–3 подряд.  
   - **Нет никогда (0 views на €5…€N)** → сначала подозрение на инвентарь/аукцион/накрутку, а не «мало ставки». Дальше п.2–3; высокий CPM без истории — только осознанно и с маленьким budget/daily.
2. **Признаки накрутки.** См. [tgads-мёртвые-площадки.md](tgads-мёртвые-площадки.md): нет/фейковый MAU у бота, огромные подп. + мёртвый ER, «бесплатно» в описании, clone; **скачок подписчиков за 1д в Telemetr** (канал / канал семьи бота); «не целить» на sibling. При сильном сигнале → статус `накрученный бот` / не целить, **не бампать**.
3. **Мёртвый канал.** Последний пост **≥ ~3 месяца** назад → не бампать; Hold + снять budget, `не целить` в Слаги. (Жёсткий архив ≥6–12 мес. — тоже kill.)

Только если п.2–3 чистые и п.1 не говорит «уже крутилось дешевле» — бамп по сетке / точечный +€ на крупном недоливе.

**Скрутка просмотров (жёстко):** если на объявлении **views ≥ 300 и clicks = 0** → это **не недолив**, а фейк показов. **Не бампать.** Hold + статус `скрутка просмотров` (см. ниже). Не путать с 0–10 views на старте.

**Evergreen на свой бот (`getsurfvpnbo`):** холодные CTR/s2t/t2b-пороги Scale **не** режут evergreen (свой бот). Лестницу недолива на нём **не** гонять. Но **Settle− обязателен**, если потолок абсурдно выше эфф. (напр. CPM €100 при эфф. ~€40–45) — см. «Абсурдный потолок» ниже.

### Приоритет воронки (главное)

Сравнение связок и решение «долить / Hold / забыть»:

1. **Покупки** — главный приоритет.
2. Если покупок ещё нет → **триалы** (это живые люди, не склик).
3. Дешёвый клик **сам по себе** не победа.

Пример: 100 кликов по €0.30 и **3 триала** vs 100 кликов по €0.70 и **30 триалов** → важнее **вторая**, хотя клик дороже.

Перед **бампами CPM сверх сетки недолива** и перед **доливом budget/daily** — сверять комплекс ниже. Сетка недолива (0 views) всё ещё поднимает ставку, чтобы получить показы; но **масштаб денег** только по воронке+CTR.

### KPI связки: CTR + s2t + t2b (обязательная сверка)

Считать по админке **`campaigns-summary_all-time`** + кабинет (не путать с `campaigns-funnel_all-time`):

| Метрика | Формула | Порог «ок» |
|---|---|---|
| **CTR** | clicks / views | **≥ 2%** (цель 2–3%+ на scale) |
| **s2t** | триалы / старты (`Пришло`) | **≥ 10%** |
| **t2b** | **покупатели** / триалы | **≥ 7%** (выше — отлично; не режем за «слишком высоко») |

**Что такое «покупатель» в summary:** это покупка **триала** (верификация **1 ₽ / 3 дня**), не обязательно полная подписка. Для t2b берём колонку **Покупателей**, не число **Покупок** (ребиллы / повторные списания раздувают Покупки).

**`campaigns-funnel_all-time` — другой срез**, не замена summary: `Регистрация` ≠ `Пришло`; `Оплатили` ≠ `Покупателей` (там дальше по воронке: счёт / полные оплаты). Ежедневный Scale/Keep/kill — только summary. Funnel — точечно, если надо понять отвал «триал → счёт → оплата».

Сигнал на объёме: ориентир **views ≥ ~500**, **starts ≥ ~15** (на меньшем n — только watch).

Желаемый CPA ~**300 ₽/покупатель** — ориентир мечты; на холодном объёме часто не бьётся (бренд/свой бот — отдельно). Не убивать связку только за CPA &gt; 300, если CTR+s2t+t2b ок и CPA ещё терпимый.

#### Уровни решения (бампать ставку / лить бюджет)

| Уровень | Условие | Действие |
|---|---|---|
| **Scale / удачная** | CTR ≥ **2%**, s2t ≥ 10%, t2b ≥ 7%, есть покупатели | Доливать budget/daily; CPM бампать **только** при недоливе |
| **Keep** | s2t ≥ 10%, t2b ≥ 7%, CTR **≥ 1%** (но &lt; 2%), CPA терпимый | Крутить; **не** агрессивно масштабировать; мелкий бамп только при недоливе |
| **Не масштабировать** | воронка ок (s2t/t2b), но **CTR &lt; 1%** на тысячах views (дорого в аукционе) | Не бампать CPM «чтобы налить»; Hold или оставить мелкий тест. Пример: technoinside vs shadownet — похожие s2t/t2b, CTR ~1% vs ~5% → CPA разъезжается |
| **Hold / отключить** | см. kill-правила ниже | On Hold; leftover снять пачкой |

Свой бот (`getsurfvpnbo`) — evergreen, KPI отдельно; эти пороги — для **холодных** channels/bots.

#### Kill / не доливать (даже если один метрик «красивый»)

- **s2t ≥ 10%, buyers = 0**, при **trials ≥ 3–5** или **spent ≥ €10** → Hold (хороший старт без денег).
- **trials ≥ 5 и t2b &lt; 7%** → Hold (много триалов, не платят).
- **CTR &lt; 1%** + уже заметный spend (**≥ €20–30**) и слабый CPA → Hold; **не** лечить ставкой.
- **CTR низкий + s2t &lt; 8%** при starts ≥ 20 → creatives/площадка мимо; Hold, не бамп.
- Старты без триалов (velvet-тип: много starts, s2t слабый) — **не** масштабировать бюджет, пока s2t не ≥ 10%.

**Stopped из‑за `daily < daily_spent`:** если связка на уровне **Scale** или **Keep** → **поднять daily (и budget при необходимости)** и вернуть Active. Не бросать победителя из‑за потолка дня.

### Сетка недолива (возраст Europe/Berlin)

Возраст = часы с первого **Active** (если в Связках пусто — с `дата`), TZ **Europe/Berlin**. Бампить только **Active**. In Review / On Hold — не бампать. Полные календарные сутки **не** обязательны для грубого шага на 0–10 views.

| Views | Возраст Active | Действие |
|---|---|---|
| **0–10** | &lt; ~12–24ч | ждать (Discovery probe) |
| **0–10** | ≥ ~12–24ч | CPM **+€1.50…€2** (грубый шаг; потолок ориентир **€7–9**). Если уже **€8–9+** → **On Hold** |
| **11–49** (типично ~30) | ≥ ~24ч, недолив | кандидат: **+€0.50** к €7–9 **или** Hold, если ставка уже высокая / смысла нет |
| **50–99** | недолив при живом daily | CPM **+€0.50** (зрелая связка) |
| **100+** | недолив при живом daily | CPM **+€0.25** (зрелая; не для старта Discovery) |
| любые | CPM **€8–9+** и мало/0 смысла в откруте после окна Discovery | **On Hold**, не +ещё €1–2 |

После бампа — `cpm` + `заметка` в Связках.

#### Ритм ревизии (2 прохода)

Отдельного крона нет; вручную **2 раза в день**:

1. **Утро — Discovery:** только Active с 0–10 views / явным недоливом → coarse bump или Hold на потолке.
2. **Вечер — Funnel:** только объёмные (≥~200–500 views или есть starts) → Keep / Scale / kill по KPI; CPM не трогать без недолива/переплаты.

В **статус-репортах** (CSV/кабинет) всегда блок **ставки Settle**: по Active с объёмом — ↑ / ↓ / не трогать по таблице «Settle: ↑ / ↓ / не трогать» выше (эфф. CPM vs потолок + views-тренд + pace daily). Discovery (0–10 views) — только сетка недолива, не Settle−. Отдельно флажить **абсурдный потолок** (ниже) и **discovery0 на cap €8–9**.

#### ROMI в каждом статус-репорте (обязательно)

Чтобы видеть прогресс от выгрузки к выгрузке, в сводке **всегда** две цифры (+ Δ к предыдущей CSV, если есть):

| Метрика | Формула |
|---|---|
| **ROMI all** | `(Доход_all − spend_all_€ × FX) / (spend_all_€ × FX)` |
| **ROMI cold** (небренд) | то же по cold: без `getsurfvpnbo` и своих каналов `surfvpnnews` / `surfvpninfo` / `surfvpninf2` |

- **Доход** = колонка «Доход, ₽» из admin `campaigns-summary_*` (атрибуция LTV, не cash за период).
- **Spend** = сумма `spent` из кабинета `adsList` (тот же срез brand/cold по `title`).
- **FX** по умолчанию **95 ₽/€** (фиксируем между репортами; смену курса — только явно в репорте).
- Дополнительно можно показать ROMI бренд+свои, но **all + cold — обязательно**. M1 не подменяет «Доход» в этой паре.
- Снимки дней: `общее/tgads-статус-YYYY-MM-DD.md` (пример: [`tgads-статус-2026-09-28.md`](tgads-статус-2026-09-28.md)).

#### ROMI на связку + аллокация бюджета (текущая стратегия)

Портфельный ROMI all/cold — для репорта. **Деньги (revive / top-up / Scale daily)** решаем по **ROMI связки**:

| Метрика | Формула |
|---|---|
| **ROMI связки** | `(Доход_₽ − spent_€ × FX) / (spent_€ × FX)` по той же паре summary+кабинет |

- **ROMI+** = ROMI связки **> 0** и есть **покупатели ≥ 1** (колонка «Покупателей»).
- **Крутим и пробуем Scale** только ROMI+: revive Stopped/Hold → Active, +budget/+daily, при Scale-KPI — агрессивнее daily. Keep (CTR 1–2%) — умеренный daily, не раздувать.
- **ROMI ≤ 0** (даже «старые любимчики» с buyers: sota t01/t04, techno, shadow…) — **не** revive и **не** top-up без явной команды «исключение». Active ROMI− не доливать; Hold/срез burn — по kill-правилам или отдельной команде.
- **Evergreen** (`getsurfvpnbo`, свои `surfvpnnews` / `surfvpninfo` / `surfvpninf2`): в cold ROMI не входят, но **долив ок** при покупках; Settle− абсурдных потолков обязателен.
- Не путать с **периодным** ROMI (Δrev vs Δspend×FX между двумя CSV) — его можно смотреть как контроль после revive; гейт аллокации по умолчанию = **LT ROMI связки**.
- Данные кабинета для аллокации — **свежий** `adsList` / баланс, не вчерашний `_cab_csv*`, если wallet уже пополняли.

Исключения (не в ROMI+ батч даже при «красивом» ROMI): `скрутка кликов` / `скрутка просмотров` / `накрученный бот` / Слаги «не целить»; CTR ≥ ~10–15% + clicks≫starts; spray одиночных one-buyer lookalike без объёма (гигиена §5).

### Гигиена портфеля (обязательно)

1. **Низкий % от суммарного daily cap ≠ «мало крутят».** При десятках Active с 0 views daily-cap портфеля завышен на бумаге; реальный burn смотреть по `daily_spent` / топ-ads, не по «€993 cap → надо бампать всех».
2. **Страховка = daily теста (€5), не низкий CPM.** Не резать потолок «на всякий случай» на холодных без переплаты.
3. **Абсурдный потолок → Settle− даже на Scale/Keep/evergreen/Search.** Если эфф. CPM устойчиво ≤ ~50–60% потолка (типично потолок ≥ ~2× эфф.) **и** есть объём — снизить потолок ≈ `эфф × 1.25…1.4` (округл. до 0.50). Сутки контроль views; сильный недолив → чуть вернуть. Search funnel не разбираем, но потолок €100 при эфф. ~€30–40 — тоже Settle−.
4. **Discovery cap жёстко:** 0–10 views и уже **€8–9+** после окна → **On Hold**, не `+€1.5`. Не бампать в тот же проход, где только что подняли до cap — дать окно до вечернего/следующего утреннего ревью.
5. **Концентрация бюджета:** +daily/budget в первую очередь на 4–6 **ROMI+** proven Scale/Keep (покупки + KPI). Не размазывать параллельный top-up на пачку lookalike/text-revive без показов или без buyers; не кормить ROMI− «по привычке».
6. **Широкий Active-портфель** (100+): утро = Discovery bump/Hold; вечер = Funnel kill/Keep/Scale. Не оставлять `kill_no_buy` Active дольше одного вечернего прохода без причины.
7. **Sota / techno-тип (CTR 1–2%, s2t/t2b ок):** Keep на умеренном daily; **не** Scale и не раздувать daily, пока CTR не ≥ 2%. Если при этом LT ROMI ≤ 0 — см. ROMI+ аллокацию (не доливать без команды).

Остальные сигналы:

| Сигнал | Действие |
|---|---|
| Воронка ок (триалы/покупки), daily доживает | **не трогать** CPM; бюджет при покупках/уверенных триалах |
| ≥50% daily за &lt;6ч **или** ≥80% daily за &lt;3ч | CPM **−~20%**; `заметка`: `переплата CPM` / `быстрый слив` |
| Settle: 2–3 дня эфф. CPM ≤ ~60–70% потолка, daily доживает, views стабильны | пробный потолок ≈ `эфф × 1.25…1.4`; `заметка`: `settle− (эфф=…)`; сутки контроль views |
| Stopped, `daily < daily_spent`, связка ок | поднять daily/budget → Active |
| Много кликов дорого, стартов/триалов мало, CTR низкий | **`дорогой клик`** |
| CTR ≥10% после ~1k | **`скрутка кликов`** |
| Target Bots, MAU большой, **views ≈ 0** сутки+ (боты «не смотрят») | **`накрученный бот`**, On Hold; в Слаги. Перед Create: MAU + dynamics канала семьи (Telemetr); **высокий MAU не гарантия** |

Не смешивать: **недолив** → сетка; **переплата** → вниз; **скрутка кликов / скрутка просмотров / дорогой клик / накрученный бот** → Hold; **воронка** → покупки > триалы > дешёвый клик.

Прочее:

1. Старт — near clearing / last clearing slug, **не** нижняя граница Recommended.
2. Channels CPM ≠ Users CPM.
3. Масштаб бюджета > теста — когда на €5 уже есть триалы (лучше покупки), не «чтобы набрать показы».
4. Темп: [tgads-snapshots/README.md](tgads-snapshots/README.md), `tgads_pace_check.py`.

€5 daily — стоп-кран. Адекватный потолок в Discovery даёт объём быстрее; низкий старт на том же кошельке только растягивает время до сигнала.

### Алгоритм любой правки в кабинете (обязательно)

Перед mutate — **preflight** по этому файлу: **Гигиена портфеля** + **ROMI+ аллокация** + Settle ↑/↓ + сетка Discovery + KPI Scale/Keep/kill. В ответе кратко: что делаем и по какому пункту (или «исключение по команде»). Без preflight массовые bump/top-up/revive не запускать. ROMI≤0 связки в top-up/revive-батч не класть без явного исключения.

Манипуляция **не завершена**, пока не обновлена вкладка **Связки** и не **проверен** кабинет после mutate. Порядок:

1. Сделать правку в кабинете (UI или `Aj.apiRequest` — см. [tgads-api.md](tgads-api.md)).
2. **Синхрон кабинета:** перезагрузить список (`/account` или свежий `adsList`) и убедиться, что `status` / `cpm` / `budget` / `daily_budget` совпали с ожидаемым. `adsList` после mutate часто **stale** — без reload не считать успех.
3. **В том же заходе** обновить колонки в **Связках** по `ad_id` / `start_param`:

| Что меняли в кабинете | Колонка в Связках |
|---|---|
| Active / On Hold / Stopped / дорогой клик / скрутка кликов / скрутка просмотров / накрученный бот | `статус` |
| CPM | **`cpm`** |
| Budget (остаток/лимит объявления) | `budget` |
| Daily budget | `daily_budget` |
| URL / title | `promote_url` / сверка `start_param` |

4. В `заметка` коротко факт (например `CPM→4 (дата, views=3)`).
5. Только после шагов 2–4 отвечать, что правка сделана.

Нельзя: поменять CPM/статус в кабинете и «потом допишу в таблицу».

**Снятие бюджета после On Hold:** не блокируем заход ожиданием ~10 мин. Остатки чистим **отдельным запросом** пачкой (`decrAdBudget`→0), когда удобно. **`deleteAd` пока не делаем.**

### Статусы качества площадки

| Статус | Сигнал | Действие |
|---|---|---|
| **дорогой клик** | CPC высокий, CTR низкий/норм, стартов/триалов мало при views | On Hold; Слаги |
| **скрутка кликов** | Высокий CTR + много кликов при **мало/0 стартов бота** (типично CTR ≥10–15% на объёме, clicks≫starts; эталон `#365` cvpn: ~30% CTR, 93 клика, 0 стартов). **ЧС даже если в summary были покупки** — покупки не отменяют паттерн склика | On Hold в тот же день; статус `скрутка кликов`; `scope=s` → Слаги **не целить** (+ семья логинов); leftover снять пачкой. Search (`tga_s_`) по starts не судим (метки нет) |
| **скрутка просмотров** | **views ≥ 300 и clicks = 0** (CTR = 0 на объёме) — точная накрутка/фейк показов | **Не бампать CPM.** On Hold + снять budget; статус в Связках `скрутка просмотров`; Слаги — не целить. Пример: nosok bot ~500 views / 0 clicks |
| **накрученный бот** | Target Bots: MAU может быть огромный, а **views ≈ 0** сутки+ (аудитория бота не видит рекламу / накрутка MAU) | On Hold; Слаги «накрученный бот»; больше не целить. Перед Create: t.me MAU + **Telemetr dynamics связанного канала** (скачок за 1д) + семья в Связках; **не верить абсолютному MAU** (у ботов в Telemetr обычно нет series) |

Признаки **мёртвых** каналов/ботов (нет MAU, крошечный канал, мёртвая лента, накрутка) — [tgads-мёртвые-площадки.md](tgads-мёртвые-площадки.md). Не путать с недоливом на крупной живой площадке.

CTR: **≥ 2%** — зона scale (вместе с s2t/t2b); **1–2%** — Keep при живой воронке; **&lt; 1%** на объёме — не масштабировать. 6–9% — жёлтая (смотреть старт/триал, не слепой масштаб). **≥ 10–15%** + клики≫стартов — скрутка кликов (ЧС даже при покупках; Search по starts не судим).

Search: метки нет — **не анализируем** воронку; крутим. Стоп только по кабинетным аномалиям.

### Модерация — блэклист формулировок

Собираем по факту Decline. Пока жёстко:

- **YouTube / Ютуб** в тексте — **не берём** (уже ловили Prohibited / удаляли).

Дальше дописывать сюда по каждому Decline (`заметка` + эта секция).

Product claims можно чуть усиливать; кабинет за лёгкое приукрашивание не банят. Не тащить саппорт-промокоды / MTProto / разовые ключи.

### Тексты t01 / t04 — как сравнивать (предложение)

Search исключаем. По tagged связкам (Channels/Bots/Users):

1. **Парный срез:** один `slug`, оба текста Active ≥N дней → winner по **покупки → триалы → старты** (дешёвый клик не победа), при ≥~20 стартов на сторону или явный разрыв.
2. **Агрегат:** trial/start и buy/start по `tx`; пока разрыв мягкий — **оба крутим**.
3. **Погашение:** слабый текст гасим точечно на проигравших slug’ах, не глобально за день.
4. Новый текст (`t05`…) — 5–10 контрольных площадок paired с лидером.

Пока t04 чуть впереди по trial/start, но не везде — **не гасим t01 глобально**.

## Target

Четыре вкладки — это четыре разных продукта. В форме дефолт: **Channels**. Код в `start_param`: Search `s`, Bots `b`, Users `u`, Channels `c`.

**Сейчас тест каналов/ботов — только один объект на ad (`scope=s`).** Не класть 10 ботов в один список: один склик/накрут убивает статистику всех, а виновника по метке не видно. Подробнее: [tgads-нейминг.md](tgads-нейминг.md) § «Поканальное / поботовое тестирование».

### Search

- **Target search queries** — список запросов (`Add search queries`).
- В URL **нет** `?start` → аналитика по метке/`bot_start` **невозможна**. Крутим; воронку по тексту/площадке не разбираем. Стоп только по кабинетным флагам (скрутка CTR, бешеный слив).
- Ad title всё равно = код связки (для учёта в кабинете и Связках).

### Bots

- **Target specific bots** — `t.me bot URL`.
- **Add similar bots** — похожие боты по выбранным.

### Users

Аудитория людей, не конкретный канал:

- **Target countries**
- **Target locations** — город, район (`Search locations by country`)
- **Target user languages**
- **Target topics** (+ *Only target users interested in all selected topics*)
- **Target channel audiences** — аудитория указанных каналов
- **Target device type:** All devices / iOS / Android / Mobile / Desktop
- **Show this ad in channels related to Politics & Incidents only**
- **Exclude topics**
- **Exclude channel audiences**
- **Do not show this ad in channels related to Politics & Incidents**

### Channels

То, что бьётся с вкладками инвентаря в таблице:

- **Target channel languages** — `Select languages (optional)`
- **Target topics** — `Select topics (optional)`
- **Target specific channels** — `t.me channel URL (optional)` + **Add similar channels**
- **Exclude topics**
- **Exclude specific channels** — `t.me channel URL to exclude`
- **Ad placement:** **Message in Channel** (дефолт) или **Banner in Video**

## Бриф одной связки

Объявление не создаём, пока нет пунктов 1–8. **Пункт 8 (админка) — до Create Ad.**

1. **Target:** Search / Bots / Users / Channels
2. **URL you want to promote** — `t.me/surfvpn?start=…` или `t.me/getSurfVpnBot?start=…` (один бот); Search без метки
3. **Ad title** (= код связки), **Ad text** (`t01`…), **Ad photo or video** (`i01`…), **Ad Button**
4. **CPM in Euro** по таблице + **Initial budget €5** + **Daily budget €5** (evergreen свой бот — отдельно)
5. Таргет: каналы / боты / запросы; slug из **Слаги** или номер списка
6. **Initial status:** On Hold
7. **Daily views limit per user:** 1
8. Код связки заведён в админке (промокоды / кампании), иначе стата не пишется
9. Перед Create — нет дубля **Ad title** / `start_param` в кабинете и Связках
10. После Create Ad — строка во вкладку **Связки**. Без строки связка не считается залитой.
11. Любое изменение в кабинете — **reload/verify** + те же цифры в **Связки** (см. алгоритм). Без синхрона не завершено.
